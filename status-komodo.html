HackiOS / Darwin XNU → Pixel 9 Pro XL

Порт ядра Apple XNU/Darwin (iOS 16, xnu-8796.141.3) на физический Pixel 9 Pro XL · codename komodo · board zumapro · SoC Google Tensor G4
RAM-only (fastboot boot) Android не тронут база: ios-tegu / ios-sweet обратная связь: фото экрана

Всё тестируется только в оперативке через fastboot boot — ничего не прошивается. UART/debug-кабеля нет; единственный канал отладки от железа — фото framebuffer-консоли.

Что уже работает (проверено на железе)

  • Сборка XNU на Linux без macOS — LLVM 18.1.8 + theos cctools (ld64) + macOS 13.3 SDK. Собирает kernel.development.tegu (Mach-O arm64 PIE) за ~2 мин.
  • Загрузка через ABL — arm64 Image-шим (flags=0xa, AVB-footer), спуск EL2 → EL1, вшитый payload KOMOXNU, старт XNU.
  • Darwin 22.6.0 грузится — ранний arm_init, MMU, kprintf.
  • Экран — AppleCLCD 1344×2992 @ 0xfac00000 (адрес из boot_args/DPU).
  • 14 ГБ верхнего банка RAM (0x880000000); окно XNU на чистом 0x98000000.
  • IOKit / TeguPlatformExpert, AppleKeyStore, Sandbox, AMFI (заглушки).
  • userspace: init запускается как PID 1 — рабочий пользовательский режим Darwin на Pixel.
  • payload вшит в образ ядра (не зависит от ramdisk ABL); chained fixups (PIE) разрешены.

Главный блокер: UFS (встроенная память)

Хост Samsung Exynos UFS (UFSHCI 3.0). При передаче управления ABL усыпляет UniPro-линк / оставляет в фатальном состоянии:
  • на handoff: HCS DP=1 (устройство на месте), PA_PWRMode 0x11 (HS, 2 линии), но DME_PEER_GET (устройство) FAIL (res 0xa);
  • UPMCRS = 5 (PWR_FATAL_ERROR); transfer-реквесты висят вечно (OCS 0xf).

Исключено (проверено): DMA/S2MPU-фенсинг, MCQ, auto-hibernate (AHIT=0), ACG/клоки (CLKSTOP=0), UTRLCLR, FMP (UFSPR_SECURE), CMU-клок, голый DME_HIBER_EXIT (→ UPMCRS=5).

Портирована вендорная последовательность выхода из H8 из mainline Linux (ufs-exynos.c + phy-gs101-ufs.c): phy_notify_state(HIBERN8_EXIT) = PMA-записи tensor_gs101_pre_h8_exit + CDR-lock перед UIC-командой. Пока не помогло — и обнаружено, что записи в PMA не применяются (чтение идёт, запись не остаётся).

Открытый вопрос для контрибьюторов

Почему записи в PMA (0x13204000) не стикаются?
  • APB-клок PHY включён (чтения идут). Изоляция PHY в PMU (0x15463EC0, bit0) из EL1 недоступна — прямой доступ даёт SError (TrustZone); ABL её уже снял.
  • Гипотезы: нужен PHY-ref-clock / спец-enable для латча записей; либо путь через secure monitor (SMC); либо реальный способ — полный HCE-reset + холодная калибровка PMA (gs101 CFG_PRE_INIT, ~60 записей) + DME_LINKSTARTUP + смена pwr-mode вместо выхода из H8.

Чего НЕ будет (честно)

  • Тач / кнопки / USB / Wi-Fi / GPU на komodo выключены — у tegu они Qualcomm (SM7150), у нас Tensor/Exynos: нужны свои драйверы (Synaptics S3908TG по SPI Samsung USI, dwc3, Mali GPU, Broadcom Wi-Fi, PMIC S2MPG14 через ACPM). Для Tensor их никто не портировал.
  • Полноценный iOS-UI (SpringBoard, аппы, анимации) как на Poco X5 Pro — там Snapdragon и драйверы уже написаны автором. Для Pixel это месяцы-годы. Реалистичный обозримый максимум — загрузка ядра + возможно лого, без рабочего ввода/сети.

Как собирать и тестировать

# 1. ядро (без macOS)
cd ~/hakios-port/xnu-linux && ./run-build.sh          # или --from 6

# 2. образ UFS-теста (RAM-only)
~/hakios-port/build-ufs.sh 0x116 xnu-ufsP-phy         # MODE PREFIX

# 3. запуск (телефон в fastboot: Питание+Громкость-вниз)
~/hakios-port/boot-ufs.sh P                           # P|A|B|C|D|R|RA|I|IC
# смотреть баннер "UFS VERDICT", фоткать

ufsmode биты: 0x1 byte-offsets · 0x2 4K PRDT · 0x4 NEXUS · 0x8 exynos-wake · 0x10 ABL-DMA-area · 0x20 FMP · 0x40 iocc-sysreg · 0x80 full-reset+relink · 0x100 PHY h8-exit assist · 0x200 PMU-isolation poke (SError, не включать).

Ключевые файлы

  • xnu-linux/.../bsd/dev/tegu_ufs.c — драйвер UFS (вся работа тут)
  • komodo/ci/tegu_ufs.c.phy-h8-exit.snapshot — актуальная копия
  • komodo/ci/0082..0092-komodo-*.patch — серия патчей поверх tegu
  • komodo/shim/ — загрузочный шим (EL2→EL1), mkxnuboot.py, komodo-base.dtb
  • Linux для портирования: drivers/ufs/host/ufs-exynos.c, drivers/phy/samsung/phy-gs101-ufs.c, phy-samsung-ufs.{c,h}
