# hakios-komodo

*[English](README.md) · Русский*

Экспериментальный порт ядра Apple XNU / Darwin (iOS 16, `xnu-8796.141.3`) на
Google Pixel 9 Pro XL (кодовое имя **komodo**, плата **zumapro**, SoC **Google
Tensor G4**).

Проект развивает линию работ ios-tegu / ios-sweet / HakiOS и использует машинный
слот `MACHINE_CONFIG=TEGU`, так как komodo относится к тому же семейству Tensor, что
и Pixel 9a («tegu»). Все проверки выполняются исключительно в оперативной памяти
через `fastboot boot`; во флеш-память ничего не записывается, штатная система Android
остаётся нетронутой.

Полное техническое описание — в [STATUS-komodo.md](STATUS-komodo.md)
(краткая версия для шеринга: [gist](https://gist.github.com/plusminusios/25461cd8e515665a7a7b350ff903e6de)).

## Текущее состояние

### Работает (проверено на устройстве)

- **Сборка.** XNU собирается на Linux без macOS с помощью LLVM 18.1.8, cctools `ld64`
  из theos и macOS SDK 13.3. Полное ядро (`kernel.development.tegu`, Mach-O arm64 PIE)
  собирается примерно за две минуты.
- **Цепочка загрузки.** Шим в формате arm64 `Image` (флаги заголовка `0xa`, AVB-footer,
  требуемый загрузчиком komodo) выполняет переход с EL2 на EL1, загружает встроенный
  payload `KOMOXNU` и передаёт управление XNU.
- **Ранний старт ядра.** Darwin 22.6.0 доходит до `arm_init`, инициализирует MMU и
  `kprintf`.
- **Дисплей.** Фреймбуфер AppleCLCD 1344x2992, базовый адрес берётся из `boot_args` / DPU.
- **Память.** Доступен верхний банк DRAM 14 ГБ по адресу `0x880000000`; окно XNU
  размещено на свободной области `0x98000000`.
- **IOKit.** Поднимаются `TeguPlatformExpert`, AppleKeyStore, Sandbox и заглушки AMFI.
- **Пользовательское пространство.** `init` доходит до **PID 1** — работающее
  пользовательское окружение Darwin на устройстве.

### Основной блокер: UFS

Контроллер накопителя — Samsung Exynos UFS (UFSHCI 3.0). При передаче управления
загрузчик оставляет UniPro-линк в состоянии hibernate / в фатальном состоянии питания:

- на момент передачи `HCS` показывает, что устройство присутствует (DP=1), а
  `PA_PWRMode` равен `0x11` (HS, две линии), но `DME_PEER_GET` к устройству
  завершается ошибкой (`res 0xa`);
- `UPMCRS` равен `5` (`PWR_FATAL_ERROR`), а запросы на передачу не завершаются никогда
  (`OCS 0xf`).

Последовательность выхода из hibernate для gs101 PHY из mainline Linux
(`ufs-exynos.c` + `phy-gs101-ufs.c`) портирована, но линк не возобновляется: запись в
блок PMA по адресу `0x13204000` не применяется, хотя чтение проходит. Управление
изоляцией питания PHY находится в PMU, принадлежащем TrustZone, и недоступно для записи
из EL1. Полный разбор и открытые вопросы — в [STATUS-komodo.md](STATUS-komodo.md).

## Структура репозитория

В репозитории хранятся только исходники; результаты сборки и сторонние тулчейны
исключены и создаются/скачиваются через `run-build.sh`.

| Путь | Содержимое |
| --- | --- |
| `xnu-linux/run-build.sh`, `xnu-linux/linux/` | сборка XNU без macOS (LLVM 18, ld64, SDK 13.3) |
| `xnu-linux/patches-src/`, `komodo/ci/*.patch` | серия патчей (база tegu + komodo `008x..`) |
| `komodo/shim/` | загрузочный шим (EL2 → EL1, встроенный payload), `komodo-base.dtb` |
| `komodo/*.py` | `mkxnuboot`, `mkadt`, `mkpayload` |
| `komodo/ci/tegu_ufs.c` | текущий драйвер UFS (активная работа) |
| `komodo/research/`, `HARDWARE-MAP-komodo.md` | заметки по реверс-инжинирингу железа komodo |
| `boot-ufs.sh`, `build-ufs.sh` | вспомогательные скрипты сборки и запуска UFS-тестов |

## Сборка

```bash
cd xnu-linux && ./run-build.sh        # скачивает тулчейны, собирает kernel.development.tegu
../build-ufs.sh 0x116 xnu-ufsP-phy    # собрать RAM-only образ UFS-теста
../boot-ufs.sh P                      # fastboot boot; читать баннер на экране
```

Устройство должно быть в режиме fastboot. Каждый образ загружается через
`fastboot boot`, поэтому ничего не прошивается.

## Границы проекта и ограничения

Тач, кнопки, USB, Wi-Fi и GPU отключены: драйверы tegu рассчитаны на компоненты
Qualcomm, тогда как komodo построен на Tensor/Exynos и требует собственных драйверов
(Synaptics S3908TG по SPI Samsung USI, dwc3, GPU Mali, Wi-Fi Broadcom и PMIC S2MPG14
через ACPM). Для Tensor они пока не портированы.

Это исследовательский порт. Полноценный интерфейс iOS, сопоставимый с демонстрацией
HackiOS на Poco X5 Pro (устройство на Snapdragon, для которого эти драйверы уже
существуют), — большая долгосрочная задача. Реалистичная ближайшая цель — загрузка
ядра и, максимум, статичное изображение на экране.

## Участие в разработке

Ближайшая задача — восстановление UFS-линка. Два конкретных направления:

1. Выяснить, почему запись в блок PMA (`0x13204000`) не фиксируется — гейтирование
   клока/enable PHY либо путь через secure world (SMC) для изоляции и калибровки.
2. Реализовать полный холодный bring-up (сброс HCE, gs101 PMA `CFG_PRE_INIT`,
   `DME_LINKSTARTUP`, смена режима питания) вместо возобновления hibernate загрузчика,
   которое стабильно завершается фатально.

Существенно помогли бы доступ к референсу Tensor UFS PHY или downstream-исходники
Google `ufs-exynos` / `ufs-cal-if` для zumapro.

## Благодарности и лицензия

XNU распространяется под лицензией APSL 2.0 (Apple). Обвязка для сборки без macOS
основана на ios-sweet-linux (APSL 2.0). Патчи, скрипты и драйверы этого репозитория
предоставляются в исследовательских целях.
